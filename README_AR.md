# دليل استخدام نظام المؤسسات

هذا الملف يشرح النظام كاملًا للمستخدم النهائي والمشرف التقني، ويغطي طريقة التشغيل والاستخدام اليومي لكل الصفحات الأساسية.

## 1. نظرة عامة

النظام مخصص لإدارة بيانات الأسر داخل مؤسسات متعددة، مع أدوار مختلفة وصلاحيات دقيقة، ويشمل:
- إدارة المؤسسات والمستخدمين.
- إدارة الأسر وأفرادها والمساعدات.
- التقارير والإحصائيات والاستيراد والتصدير.
- سجل النشاط والجلسات.
- صفحة فحص الصحة والنسخ الاحتياطي.

## 2. الأدوار والصلاحيات

الأدوار الأساسية:
- `developer` (المطور): يرى كل المؤسسات وكل البيانات، ويضبط النظام بالكامل.
- `admin` (مسؤول المؤسسة): يرى ويعدل بيانات مؤسسته فقط.
- `data_entry` (مدخل بيانات): إدخال/تحديث بيانات الأسر حسب الصلاحيات الممنوحة له.

قواعد مهمة:
- المسؤول يرى النشاط والجلسات الخاصة بمؤسسته فقط.
- مدخل البيانات لا يرى صفحة النشطين/الجلسات.
- صلاحيات المستخدمين يمكن تعديلها من صفحة صلاحيات المستخدم (للمطور).

## 3. الدخول للنظام

1. افتح صفحة `login`.
2. أدخل البريد/اسم المستخدم وكلمة المرور.
3. بعد الدخول يتم تحويلك إلى لوحة التحكم `dashboard`.

## 4. التنقل بين الصفحات

الصفحات الرئيسية في الشريط العلوي (حسب الدور):
- لوحة التحكم: `dashboard`
- الأسر: `families`
- المساعدات: `benefits`
- التقارير والإحصائيات: `reports`
- الإشعارات: `notifications`
- النشاط: `activity-logs` (حسب الصلاحية)
- الجلسات/النشطون: `sessions` (developer/admin مع صلاحية)
- فحص الصحة: `developers/health` (للمطور)

## 5. إدارة المؤسسات والمستخدمين

### 5.1 إضافة مسؤول مؤسسة (للمطور)
من صفحة:
- `developers/administrators`

يمكنك:
- إنشاء مسؤول جديد وربطه بالمؤسسة.
- رفع شعار المؤسسة أثناء إنشاء/تعديل المسؤول.
- تعديل بيانات المسؤول أو حذفه.

ملاحظة:
- شعار المؤسسة يظهر في صفحات المسؤول ومدخل البيانات المرتبطة بنفس المؤسسة.

### 5.2 إدارة مدخلي البيانات (للمسؤول)
من صفحة:
- `admin/data-entry-users`

يمكنك:
- إضافة مدخل بيانات.
- تعديل بياناته.
- تعطيله/حذفه حسب الصلاحيات.

## 6. إدارة الأسر

من صفحة `families`:
- إضافة أسرة جديدة.
- تعديل أسرة موجودة.
- حذف أسرة.
- البحث والتصفية.
- تصدير بيانات الأسر.

### 6.1 قواعد مهمة في البيانات
- التحقق من عدم تكرار الأسرة داخل نفس المؤسسة باستخدام رقم هوية رب الأسرة (`head_national_id`).
- في الاستيراد أيضًا يتم تجاهل/منع التكرار بنفس القاعدة.

### 6.2 عدد أفراد الأسرة (مفعل تلقائيًا)
- إذا الحالة الاجتماعية: `متزوج` أو `متزوجة`
  - العدد = عدد الأفراد + رب الأسرة + الزوج/الزوجة.
- إذا أي حالة أخرى
  - العدد = عدد الأفراد + رب الأسرة.

### 6.3 رقم الجوال للأفراد
- يتم تعبئة رقم جوال الفرد تلقائيًا من رقم جوال رب الأسرة.
- إذا تُرك جوال الفرد فارغًا، النظام يستخدم رقم جوال رب الأسرة تلقائيًا.

## 7. المساعدات

من صفحة `benefits`:
- إضافة سجل مساعدة للأسرة.
- عرض المساعدات المسجلة.
- حذف سجل مساعدة عند الحاجة.

## 8. التقارير والإحصائيات

من صفحة `reports`:
- عرض مؤشرات وإحصائيات عامة.
- تصدير الأسر: `reports/families-export`
- تصدير الإحصائيات: `reports/statistics-export`

### 8.1 استيراد بيانات الأسر
من نفس صفحة التقارير:
- رفع ملف استيراد الأسر.
- النظام يدعم الامتدادات المختلفة طالما المحتوى قابل للقراءة النصية بصيغة جدول.

ما الذي يدعمه الاستيراد فعليًا:
- اكتشاف فاصل الأعمدة تلقائيًا: `,` أو `;` أو `tab` أو `|`.
- التعامل مع رؤوس أعمدة عربية/إنجليزية (aliases).
- تخطي سطور تمهيدية قبل رأس الجدول.
- وضع بديل عند غياب الرأس (يأخذ أول عمودين كاسم رب الأسرة ورقم الهوية).
- في استيراد المطور: يمكن اختيار المؤسسة من الصفحة إذا لم تكن موجودة داخل الملف.

أخطاء شائعة في الاستيراد:
- `head_name and head_national_id are required`
  - السبب: الأعمدة غير موجودة أو غير مُعرّفة بشكل صحيح.
- `column count mismatch`
  - السبب: فاصل الأعمدة غير موحد أو صفوف مكسورة.
- `institution_id or institution name is required for developer import`
  - السبب: لم تُحدد مؤسسة داخل الملف ولم يتم اختيارها من نموذج الاستيراد.

## 9. تقرير أبناء الأرامل/الأرملة

متاح ضمن صفحة `reports`:
- البحث حسب الحالة الاجتماعية (`أرمل` / `أرملة`).
- عرض النتائج في جدول.
- تنزيل النتائج كملف CSV من:
  - `reports/widows-export`

## 10. النشاط والجلسات (النشطون)

### 10.1 سجل النشاط
من صفحة `activity-logs`:
- يعرض العمليات المنفذة داخل النظام.
- المسؤول يرى نشاط مؤسسته فقط.

### 10.2 صفحة الجلسات/النشطون
من صفحة `sessions`:
- للمطور: رؤية جميع النشطين.
- للمسؤول: رؤية النشطين في مؤسسته فقط.
- مدخل البيانات: غير مسموح له بالوصول لهذه الصفحة.

## 11. الإشعارات

من صفحة `notifications`:
- عرض جميع الإشعارات.
- تعليم الكل كمقروء.

## 12. فحص الصحة والنسخ الاحتياطي

### 14.1 صفحة فحص الصحة
من `developers/health`:
- تعرض حالة المكونات المهمة (قاعدة البيانات، التخزين، الطوابير... حسب الإعداد).
- الهدف: التأكد السريع من جاهزية النظام.

### 14.2 تشغيل النسخ الاحتياطي
من نفس الصفحة:
- زر/إجراء `run-backup` لتشغيل النسخ الاحتياطي.
- راقب نتيجة التنفيذ وتأكد من حفظ النسخة في مسار التخزين المعتمد.

## 13. واجهة مرنة (Responsive)

تم تحسين العرض للعمل على:
- سطح المكتب.
- الأجهزة اللوحية.
- الجوال.

مثال:
- صفحة الأسر تعرض جدولًا على الشاشات الكبيرة وبطاقات على الجوال.

## 14. واجهة API

نقاط API المتاحة:
- `GET api/v1/families`
- `GET api/v1/families/{family}`

تُستخدم للتكامل الخارجي أو تطبيقات أخرى مع مراعاة المصادقة والصلاحيات.

## 15. تشغيل المشروع محليًا (للمطور التقني)

1. تثبيت الاعتمادات:
```bash
composer install
npm install
```
2. إعداد البيئة:
```bash
cp .env.example .env
php artisan key:generate
```
3. ربط التخزين العام للشعارات والملفات:
```bash
php artisan storage:link
```
4. التهجير (و seed إن لزم):
```bash
php artisan migrate
```

## 16. تطبيق ويندوز (Desktop)

تمت إضافة نسخة سطح مكتب لويندوز باستخدام Electron، وتعرض نفس النظام الموجود على الويب.

### 16.1 تشغيل نسخة التطوير
يشغّل خادم Laravel ثم يفتح تطبيق سطح المكتب:

```bash
npm run desktop:dev
```

### 16.2 تشغيل التطبيق مباشرة
يفتح تطبيق سطح المكتب فقط (يتوقع أن الخادم يعمل):

```bash
npm run desktop:start
```

### 16.3 بناء نسخة ويندوز
يبني ملف Installer ونسخة Portable:

```bash
npm run desktop:build-win
```

ملفات الإخراج:
- `desktop-dist/ESNAD Institutions Setup 1.0.0.exe`
- `desktop-dist/ESNAD Institutions 1.0.0.exe`

### 16.4 ربط التطبيق بعنوان منشور بدل المحلي
العنوان الافتراضي الدائم لتطبيق ويندوز موجود في:
- `electron/desktop.config.json` ضمن المفتاح `productionUrl`

كما يمكن تجاوزه مؤقتًا عبر متغير البيئة.

لتوجيهه إلى رابط النظام المنشور:

```bash
set DESKTOP_APP_URL=https://your-domain.example
npm run desktop:start
```
5. تشغيل التطبيق:
```bash
php artisan serve
npm run dev
```

## 16. فحص سريع عند أي مشكلة

نفذ التالي:
```bash
php artisan optimize:clear
php artisan config:clear
php artisan route:clear
php artisan view:clear
```

ثم تحقق من:
- صلاحيات المستخدم.
- المؤسسة المرتبطة بالمستخدم.
- تنسيق ملف الاستيراد.
- سجلات الأخطاء في `storage/logs/laravel.log`.

## 17. ملاحظات تشغيلية

- أي مستخدم من نوع مسؤول أو مدخل بيانات يجب أن يكون مرتبطًا بمؤسسة صحيحة.
- رفع شعار المؤسسة يحتاج ربط `storage` بشكل صحيح (`storage:link`).
- قبل استيراد ملفات كبيرة، يفضل تجربة ملف صغير أولًا للتأكد من الترويسات والفواصل.

## 18. ملخص الاستخدام اليومي

1. سجّل الدخول.
2. راجع لوحة التحكم.
3. أدخل/حدّث الأسر.
4. سجّل المساعدات.
5. راجع التقارير وصدّر النتائج.
6. (للمسؤول/المطور) راقب النشاط.
7. (للمطور) نفّذ فحص الصحة والنسخ الاحتياطي دوريًا.
